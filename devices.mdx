Open your profile menu, then **Settings → Account → Security → Devices**. This page helps you review browser access, device requests, and signed-in sessions.

## Review a device

Check the device status and **Last seen** before changing access. A request can show **Approval pending** or a device can be **Temporarily blocked**. Use **Rename** to give a browser a name you recognize. Renaming does not change its access.

For a pending request, verify it came from a browser you control. The request may show a QR code, short code, matching phrase, and expiry. Use **Copy link** or **Open on an approved device** when available, then compare the phrase before continuing. Complete approval only through a confirmation control shown in the app. If none appears, do not guess; use **Can’t use another device?** when available or contact us.

If a request expires, choose **Try again** when available. Never approve an unfamiliar request or share its link or code with someone else.

## Pause or remove device access

Choose **Temporarily block** to pause a device’s access. Choose **Restore access** to reverse the block. Blocking is not a remote wipe of information already on that device.

For another browser, open its action menu and choose **Remove**, then confirm with **Remove device**. This signs out that browser and revokes its approval; offline copies may remain.

For this browser, choose **Remove this browser**, then confirm with **Remove browser**. This clears the encrypted workspace on this browser and signs it out. Save anything you need first.

Choose **Cancel request** to withdraw a pending device request.

## Manage browser sessions

Under **Other signed-in browsers**, use the session actions to end access:

| Control | What it does |
| --- | --- |
| **Sign out** or **End session** | Ends the selected browser session. |
| **Sign out everywhere** | Ends every browser session, including this one. Local encrypted data is not deleted. |

Signing out ends a session. It does not by itself delete account data or local encrypted data.

## If a device or session is missing

Return to Devices and check the status again. If the list still looks wrong or an action fails, read the message shown in the app and [contact us](/contact) with the visible error. Do not include sign-in codes, recovery material, passwords, or private health information in public feedback.
