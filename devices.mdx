Open your profile menu, then **Settings → Account → Security → Devices**. A signed-in browser and an approved sync device are not the same thing: signing in does not always mean this browser can read your encrypted synced data.

## Set up sync

If you see **Set up encrypted sync**, finish and verify your [account recovery kit](/security#save-an-account-recovery-kit) first. Return to Devices and choose **Turn on sync** when it becomes available. The browser must be approved before it can use encrypted sync.

Do not clear your only working browser before checking that your important information is available on another approved device.

## Approve a new browser

1. On the new browser, open Devices. A pending browser shows an approval QR code, a link, a matching phrase, and an expiry countdown.
2. Open that link on a browser you already trust and use for this account. You can scan the QR code or use **Copy link**.
3. Review the device identity and compare the matching phrase on both browsers.
4. Choose **Approve device** only if the phrase matches exactly and you recognize the request. Otherwise choose **Cancel**.

If the request expires or cannot be created, follow the displayed retry or verification instructions. Never approve a request simply because someone sends you a link.

If no approved browser is available, expand **Can’t use another device?** and follow the recovery options shown for your account. Recovery needs the appropriate saved material or verification; it is not a way around account security.

## Read device status

The current browser shows its status, last-sync time, and the number of approved devices. An approved device is allowed to sync; that status alone does not prove every change has finished transferring. Check the sync status and waiting-change count too.

Use **Rename** to give a browser a name you recognize, such as “Home laptop.” Renaming does not grant it additional access.

## Automatic sync

The **Automatic sync** switch pauses or resumes automatic transfers. Pausing does not delete existing information. Automatic transfers run while the app is open; do not assume they continue after you close it.

Open **Advanced sync controls** for the following options.

### What syncs

Each switch controls a supported category:

| Category | What it covers |
| --- | --- |
| Preferences | Supported response preferences, shortcuts, and sidebar choices. |
| Chats | Finished messages and conversation details. |
| Projects | Project details and which chats belong to them. |
| Memory | Saved memory information and its review and consent records. |
| Health avatar | The saved health-avatar information rebuilt from reconciled memory. |
| Files | Encrypted file information and supported documents, images, and media. |

Turning a category off is not an instruction to delete copies that already exist. These switches are not a promise that every browser setting or every item on your computer is synchronized.

### Transfer mode

**Automatic** lets supported transfers run automatically while the app is open. **Manual** leaves transfers for you to start with **Sync now**. The master Automatic sync switch and transfer mode are separate controls.

### Monthly upload limit

Set an optional monthly upload cap. The field takes a number of **bytes**, not MB. For example, 100000000 is about 100 MB. Leave it empty for no user-set cap. This does not remove any service or plan limits.

### Storage and transfer readings

**On this device** refers to local sync storage; **Cloud files** refers to encrypted cloud storage. **Uploaded** and **Downloaded** show transfer usage for the reporting period. These are different measurements, not values that should always match.

### Sync now

Choose **Sync now** to attempt an upload of waiting changes and pull available updates. It can request a transfer even when automatic transfers are paused or set to Manual. It does not bypass device approval, connectivity, or service limits. Read any error and check the waiting count afterward.

## Temporarily block another device

Open that device’s action menu and choose **Temporarily block**. Use **Restore access** to reverse the block. This is different from removing the device and is not a remote wipe of information already on it.

## Sign out or remove access

| Action | What happens |
| --- | --- |
| Sign out | Ends this browser’s sign-in session. It is not the same as removing its local data. |
| Remove this browser | After confirmation, revokes this browser’s device access, clears the active account’s local workspace here, and signs out. Save anything you need first. |
| Remove another device | Revokes its sync access and signs it out. Offline copies may remain; this is not a guaranteed remote wipe. |
| Cancel request | Removes a pending device approval request. |
| Sign out everywhere | Ends every browser session, including this one. Local encrypted data is not deleted by this action. |

Advanced controls may also list **Other signed-in browsers**. Ending one of those sessions removes that sign-in session; do not confuse it with deleting the account.

## If sync needs attention

Read the message in Devices, check your connection, and confirm this browser is approved. If recovery setup is unfinished, complete it before relying on sync. Avoid clearing local storage to fix a sync error when it may contain your only copy.

For help, [contact us](https://anistratenco.com/contact) with the visible error and support reference. Do not include an approval token, recovery key, or private health information unless it is specifically needed for your request.
